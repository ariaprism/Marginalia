# Marginalia 技术与产品决定

## 2026-07-27：痕迹只存 Locator，句子索引每次重算

### 背景

划线与批注此前是 `App.tsx` 里的 `useState`，初值来自一个硬编码常量，刷新即丢。要落库就必须先决定「一条痕迹存在哪里」。

阅读器的交互粒度是「本章第几句」，最省事的做法是把句子索引存进去。但句子索引是 `Intl.Segmenter` 分段的副产品：改一次分段逻辑、清洗规则或段落提取，全书索引会整体漂移，而库里的旧数据无法自我修正。

### 决定

- 持久层只保存 `Locator`（`chapterIndex` + `elementPath` + `textOffset` + `selectedText` + 前后文），不保存句子索引。
- 句子区间是运行时缓存，每次加载时由 `resolveLocator` 从 Locator 重新算出来，按 `EPUB_ANCHORING.md` 第 4 节逐级降级。
- 段落下标即 `elementPath` 首段：`collectParagraphs` 每个块级元素产出一个段落，正好对应「本章第几个可产生文本的块级元素」。行内元素暂不参与分段，路径只有一层。
- 一条痕迹的主键是 `passageKey = chapterIndex|elementPath|textOffset|selectedText`。它是内容派生的，重新导入同一本书时旧痕迹会自动重新归组。
- 同一句子的划线与多条批注归到同一条痕迹；`Highlight` / `Annotation` / `Marginalia` 三张表在加载时合成一个 `Trace` 视图模型。
- 原文已经找不回来的痕迹标记 `drifted`：仍然列在痕迹面板里，但不提供跳转。宁可让用户看到一条无法跳转的旧批注，也不能让它静默消失。

### 影响

- 分段逻辑将来可以自由调整，不会作废库里已有的痕迹。
- 阅读器渲染与 Locator 换算必须共用 `segmentChapter`，否则两边句子编号对不上。
- 示例书《雨夜书房》的痕迹改为首次运行播种进同一批表，预览书与导入书共用一条读写路径，界面上不再有一半来自内存、一半来自数据库的状态。播种是幂等的，并且以章节自己声明的 `highlight` 子串为准，不再重抄一遍引文——原先抄的 `句子需要重量。` 与正文的 `句子需要重量：` 已经不一致，那条痕迹一直静默播不进去。
- 落库后暴露出三个此前不可见的缺陷，一并修掉：同毫秒写入的批注共享 `createdAt` 导致重载后顺序不定（改为严格递增的时间戳 + id 兜底排序）；`openMarginaliaDB` 每次调用重开库，`loadTraces` 的三个并发读会互相抢 schema 升级（按 `IDBFactory` 缓存连接）；测试共用同一个库导致写入互相污染（每个用例换一个空 `IDBFactory`）。

## 2026-07-26：Phase 1B 进入真实 EPUB 与本地持久化

### 背景

Phase 1A 视觉原型已收口。下一目标是从静态视觉稿过渡到可导入、可保存、可重读的真实书籍。需要先确定数据模型与本地存储边界，再修改 UI。

### 决定

- 在 `src/domain/` 定义不依赖 React、浏览器或 Supabase 的核心对象：`Book`、`Chapter`、`Locator`、`ReadingProgress`、`Highlight`、`Annotation`、`Marginalia`。
- 定位使用 `chapterIndex` + `elementPath` + `textOffset` + `selectedText` + 上下文，CFI 仅作辅助；动态页码只用于显示。
- 浏览器内使用 JSZip 解析用户上传的 EPUB，先提取元数据、目录与章节 HTML。
- 使用 IndexedDB 持久化：books、epubFiles、chapters、readingProgress、highlights、annotations、marginalia。
- 先完成存储层与解析器，再逐步接入现有书架和阅读器 UI，替换硬编码的模拟书籍。

### 影响

- `src/App.tsx` 中的硬编码书籍与章节数据最终会被本地数据取代，但视觉结构保持不变。
- 阅读器需要先清洗 EPUB 章节 HTML，再渲染句子单元；原有 sentence segmenter 逻辑需要适配 HTML 输入。
- 测试使用 `fake-indexeddb` 模拟 IndexedDB，避免测试依赖真实浏览器环境。

## 2026-07-19：第一版阅读器改为分页优先

### 背景

施工地图最初计划第一版优先滚动阅读，到后续阶段再增加翻页模式。视觉讨论后，确认左右分页更符合 Marginalia 的纸质书隐喻和安静阅读体验。

### 决定

- Phase 1A 的视觉原型直接采用左右分页。
- Phase 1B 的真实 EPUB 阅读器以分页为主要阅读方式，不再把翻页推迟到 Phase 6。
- 页面左侧 40% 用于上一页，右侧 40% 用于下一页，中间 20% 用于唤起或收起阅读工具。
- 文字选择、已有划线和交互控件优先于翻页点击。
- 顶栏和五区底栏默认隐藏；正文内部平常不显示返回键。

### 影响

- EPUB 页码是当前窗口和排版设置下的动态页码，不能作为稳定定位依据。
- 阅读位置、划线与批注仍需保存结构定位、原文和上下文，改变字号后重新计算页码。
- Phase 1B 需要更早处理分页、跨元素选区和改变排版后的重锚定。

## 2026-07-19：Phase 1A 使用原创模拟样书

### 决定

视觉原型使用原创短篇《雨夜书房》和模拟批注，不依赖真实 EPUB、云端或 AI 接入。真实 EPUB 留到 Phase 1B 验证。

## 2026-07-19：书架与阅读入口分层

### 决定

- 手机书架使用混合卡片：封面与基本信息横排，最近停留独占下一行。
- 点击封面进入该书的“小房间”，集中展示简介、进度、最近停留、章节和痕迹。
- 点击书籍信息或“继续阅读”直接回到正文；点击最近停留直接跳到对应痕迹。
- 书架首页不再显示大幅宣传标题，使书籍成为首屏主体。

## 2026-07-19：排版变化必须触发真实重分页

### 决定

阅读正文保持连续内容流，并根据可用页面尺寸自动分栏。字号、行距、页边距或屏幕尺寸变化时重新计算页数，不得通过隐藏溢出内容维持固定页数。

## 2026-07-20：“最近停留”表示阅读位置

### 决定

- “最近停留”保存用户最后阅读时的章节、稳定正文定位、进度及附近原文预览。
- 返回书架、应用进入后台或页面关闭前，应保存当前阅读位置。
- 最近划线和最近批注是不同概念，不得用来替代最近停留。
- 点击最近停留应回到原阅读位置；排版变化后仍通过稳定定位找到同一句附近。

## 2026-07-20：不同入口采用不同痕迹顺序

- 书籍小房间作为全书地图，按章节顺序及原文位置顺序展示全部痕迹。
- 阅读器底栏作为最近活动入口，按创建时间倒序展示痕迹。

## 2026-07-20：字体按内容角色划分

### 决定

- 展示衬线体用于品牌、书名、章节标题、封面和引用原文，保留书卷气。
- 手机系统无衬线字体用于按钮、状态、简介、最近停留、统计和其他功能界面，提高小字号可读性。
- 阅读正文使用独立字体角色，第一版提供“书页宋体”和“清晰黑体”两种真实生效的选择。
- 字体变化与字号、行距、页边距一样触发动态重分页，并尽量保留当前章节内的阅读位置。

## 2026-07-20：默认浏览器主题色采用深一层的暖纸色

- 页面主背景保持 `#f1e8d8`。
- 浏览器地址栏和未来 PWA 外壳使用 `#e5d7c3`，与页面同色相但略深，形成克制的书页边界。

## 2026-07-21：主页提供两种书架视图

- 点击主页的 Marginalia 品牌区，在信息列表与三列封面书架之间切换。
- 信息列表用于继续阅读和查看最近停留；封面书架用于紧凑浏览藏书，只展示封面。
- 两种视图共享书架分类筛选；封面书架点击封面统一进入书籍小房间。

## 2026-07-21：书架索引与章节标题减少信息层级

- 书架分类使用中文衬线标签，不显示书籍数量；数量只保留在无障碍名称中。
- “章节与痕迹”使用中等字重衬线体，由一枚自绘页边痕迹图标承担视觉锚点，不再叠加英文眉题。

## 2026-07-21：正文优先使用连续句子点选

- 阅读正文按句子拆分为可点击单元，默认关闭浏览器原生文字选择与系统长按菜单。
- 单击选择一句，点击相邻句扩展连续范围，点击选区边界句收缩；点击正文空白先清空选择，不同时翻页。
- 复制、划线和“留痕”使用贴近选区的小型上下文气泡，不显示关闭按钮、文字预览、颜色或线型设置。
- 第一版暂不实现任意字符自由选择；划线使用默认或上次使用的样式。
- 同一句子范围只有一条痕迹记录；划线与批注更新同一记录，避免重复。已有划线时操作按钮切换为“抹去”。
- 用户主动划线显示雾粉色高亮；只写批注而未主动划线时显示豆沙色虚线。痕迹面板和书籍小房间的引文沿用相同线型。
- 批注操作采用“留痕 → 留下 → 重温”的叙事；保存后先呈现只读痕迹卡，需要修改或删除时从卡片的 `···` 进入“修订／抹去文字”。
- 正文划线详情只展示带对应线型的引文、人物、轻量时间戳和批注内容；不重复章节信息，不显示关闭叉号或底部划线操作栏，点击卡片外关闭。
- 同一句子范围允许按时间追加多条用户批注；每条批注拥有独立时间与修订／抹去入口，重温卡底部始终保留继续留痕的输入区。
