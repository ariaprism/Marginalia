# Marginalia EPUB 定位与重锚定策略

> 本文定义 Marginalia 如何在 EPUB 中稳定记录阅读位置、划线、批注与她留下的文字。
>
> 核心原则：**动态页码只用于显示，不能作为持久定位依据。**

---

## 1. 为什么 EPUB 页码不稳定

EPUB 是重排流式文档：

- 同一本书在不同字号、行距、页边距或屏幕宽度下会重新分页。
- 章节内的“第 N 页”没有跨设备、跨排版的稳定意义。
- 因此 Marginalia 不把页码写入持久层，也不允许 URL fragment 使用页码。

PDF 才具有稳定的物理页码；Marginalia 第一版不处理 PDF。

---

## 2. 持久定位需要保存什么

每个需要定位的实体（阅读位置、划线、批注、未来痕迹）都持有一个 `Locator` 值对象，包含：

| 字段 | 说明 | 优先级 |
|---|---|---|
| `bookId` | 书籍唯一标识。 | 必需 |
| `chapterIndex` | spine 中的章节索引。 | 必需 |
| `elementPath` | 章节 DOM 中稳定的元素路径，例如 `[2, 0]` 表示第 3 个块级元素内的第 1 个文本节点。 | 必需 |
| `textOffset` | 元素内文本偏移量（字符数）。 | 必需 |
| `selectedText` | 用户选中的实际文本。 | 必需 |
| `beforeContext` | 选中位置前约 50 个字符。 | 必需 |
| `afterContext` | 选中位置后约 50 个字符。 | 必需 |
| `cfi` | EPUB CFI（Canonical Fragment Identifier），如果解析器能可靠生成。 | 推荐 |

### 2.1 元素路径规则

- 从章节根元素开始计数。
- 只遍历产生文本内容的元素节点，忽略空白文本节点或纯装饰节点。
- 路径中的数字是“同层级可产生文本的子元素”的索引，而不是 DOM 所有子节点的索引。
- 示例：`<section><h1>…</h1><p>…</p><p>…<em>…</em></p></section>` 中，第二个 `<p>` 的路径是 `[2]`，其中 `<em>` 内文本的路径是 `[2, 0]`。

### 2.2 CFI 的使用边界

- CFI 是首选的跨解析器定位方式。
- 某些 EPUB（尤其旧版或制作不规范的）可能缺少可解析的 CFI 基础，因此 CFI 作为可选字段。
- 持久层同时保存 `elementPath` + `textOffset` + `selectedText` + `context`，CFI 仅作为辅助匹配。

## 3. 阅读位置如何保存

`ReadingProgress` 同样使用 `Locator`：

- 用户正常前后翻页、在当前页划线或批注、主动移动折页或退出阅读器时，记录当前可见区域顶部附近的句子。
- 保存该句子的 `chapterIndex`、`elementPath`、`textOffset`、`selectedText` 与上下文。
- 下次打开书籍时，优先按 CFI 跳转；失败时按元素路径 + 文本匹配；再失败时按上下文模糊匹配。
- 从目录、痕迹或章节列表直接跳转先视为临时翻看，不立即覆盖自动继续位置；在新位置继续产生阅读动作后才推进。

### 3.1 “上次读到”不是最近划线

- 阅读位置与最近划线、最近批注是不同概念。
- 用户可能读到某处但没有划线；退出时仍应回到该处。
- 书架上的“上次读到”应显示保存阅读位置时的章节与附近原文预览。

### 3.2 每本书的一枚折页

- `ReadingProgress.locator` 是系统自动保存的继续阅读位置。
- `ReadingProgress.bookmark.locator` 是用户手动留下的唯一折页。
- 两者互不覆盖：继续阅读默认回自动位置，折页通过顶栏入口单独返回、移动或取消。
- 自动位置与折页都使用稳定 Locator，不保存当前排版产生的动态页码。

## 4. 重锚定策略（Reanchoring）

当书籍内容变化（例如重新导入新版 EPUB、用户调整字号导致 DOM 结构不变但文本偏移变化）或解析器无法直接命中时，按以下顺序重锚定：

1. **CFI 精确匹配**：如果 `cfi` 存在且当前 DOM 能解析，直接定位。
2. **元素路径 + 文本偏移匹配**：在相同 `chapterIndex` 和 `elementPath` 处检查 `selectedText` 是否一致；一致则直接使用。
3. **元素内文本搜索**：在同一元素内搜索 `selectedText`；找到唯一匹配时采用新偏移。
4. **章节内上下文匹配**：在同一章节内搜索 `beforeContext + selectedText + afterContext` 的子串；找到时以该位置为中心重建 Locator。
5. **退化到最近已知位置**：如果以上都失败，回到章节开头，并在 UI 中提示用户位置可能已漂移。

### 4.1 上下文匹配的安全边界

- 上下文只用于定位，不用于显示。
- 如果同一章节出现多处相同上下文（例如重复的标点或诗句），优先选择距离原 `elementPath` 最近的一处。
- 重锚定完成后，保存新的 `Locator`，保留旧的作为历史参考。

### 4.2 实现现状（2026-07-27）

本节的降级策略实现在 `src/reader/sentenceAnchor.ts` 的 `resolveLocator`，与上面的规格有两处已知偏差：

- **没有 CFI**。第 1 步跳过，实际从第 2 步（元素路径 + 文本偏移）开始。当前解析器不生成 CFI，`Locator.cfi` 始终为空。
- **原位命中要求原文与前文同时相符**。只比对 `selectedText` 不够：对话、诗行、「他说。」这类结构重复的书里，同一个偏移在别的段落上也能字字相符，划线会静默钉在错误的那一处。前文不符时该候选降级为兜底，等带上下文的搜索全部失败才退回来用。

失败时的处理也比第 5 步更保守：不回到章节开头，而是把痕迹标记为 `drifted`——仍然列在痕迹面板里，但不提供跳转。

句子索引不进持久层，每次加载时由本函数重新算出来；理由见 `DECISIONS.md`（2026-07-27）。

## 5. 显示用页码如何计算

- 阅读器在渲染时使用 CSS columns 把连续章节流切成可视页面。
- 总页数 `totalPages` 和当前页 `pageIndex` 只存在于运行时的 React state 中。
- 页码根据字号、行距、页边距、屏幕宽度动态重算。
- 不保存 `pageIndex` 到 IndexedDB 或 Supabase。

## 6. 划线、批注与她的文字

### 6.1 Highlight

- 用户主动划线时创建 `Highlight`。
- `Highlight.locator` 保存定位信息。
- 划线颜色：雾粉（rose）、淡金（gold）、薄荷（mint）。

### 6.2 Annotation

- 用户对某段文字写想法时创建 `Annotation`。
- 可以依附于已有的 `Highlight`（`highlightId`），也可以独立存在。
- 独立批注同样需要 `Locator`，以便在正文里显示为虚线下划线。

### 6.3 Marginalia（她留下的文字）

- 依附于一条 `Annotation`。
- 使用同一句子的 `Locator`；如果是未来痕迹，目标位置可能在用户尚未到达的章节。
- `visibility = reveal_on_reach` 时，前端在用户到达对应位置前不渲染；到达后按普通痕迹显示。

---

## 7. 微信读书影子书的定位

- 影子书只有划线、想法，没有完整正文。
- 导入时保存来源提供的章节标识、划线原文和上下文。
- 当用户后续导入对应 EPUB 时，用本章重锚定策略把旧划线绑定到真实正文；匹配失败的保留为“待匹配”。

---

## 8. 第一版不做的事

- 不保存固定页码。
- 不支持跨 EPUB 版本自动合并漂移过大的批注（只尽力重锚定，失败时提示）。
- 不处理扫描版 PDF 或图片式 EPUB。
- 不把整章正文作为定位依据；只保存选中位置附近的局部上下文。

## 9. 验收标准

- [x] 改变字号或行距后，同一句话的高亮与批注仍落在正确位置。
- [x] 刷新后重新打开书籍，阅读位置回到退出前自动保存的句子。
- [x] 同一句子可以有多条用户批注，每条批注使用相同的 `Locator`。
- [ ] 未来痕迹在用户未到达目标位置前保持隐藏。（`visibility` 字段已定义，前端未实现）
